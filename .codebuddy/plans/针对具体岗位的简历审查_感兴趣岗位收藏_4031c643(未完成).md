## 用户需求

当前简历审查 Agent 是基于「整个数据库」做泛化 Gap 对比（按城市/类别模糊匹配后对比所有岗位），用户认为这种方式没有针对性、不实用。用户要求改为**针对具体岗位的 JD 要求**来审查简历。

## 产品概述

在数据展示模块为岗位增加「感兴趣」收藏功能，把求职者感兴趣的岗位暂存到求职助手模块（基于 session，等候调用）。当进入求职助手的简历审查页时，可从「我感兴趣的岗位」清单中勾选一个或多个具体岗位，系统只针对这些岗位的 JD 做技能/学历/经验 Gap 分析，并生成聚焦该岗位的 AI 诊断与优化简历。未勾选时仍保留城市/类别兜底模式。

## 核心功能

- 数据展示页（/data）每行新增「感兴趣」按钮，点击收藏/取消，带角标状态、不触发整行跳转。
- 岗位详情页（/job/&lt;id&gt;）新增「感兴趣」按钮，与列表页共用同一收藏逻辑。
- 收藏的岗位存入 `session['interested_jobs']`（整型 id 列表），跨页面持久，零数据库迁移。
- 求职助手简历审查页新增「我感兴趣的岗位」多选清单（默认全选），提交后作为 `target_job_ids` 传入审查逻辑。
- `review_resume` 支持 `target_job_ids` 参数：仅查询这些具体岗位并做针对性 Gap 分析与 LLM 上下文聚焦；不传则走原城市/类别兜底。
- 支持一次勾选多个岗位，分别给出各自的 Gap 诊断与优化建议。
- 导航栏「求职助手」旁显示已收藏数量角标（可选增强）。

## 技术栈

- 后端：Flask 3.x（沿用现有 Jinja2 服务端渲染，无前后端分离）
- 状态存储：`session['interested_jobs']`（list[int]），与项目现有 `compare_state`/`match_state`/`review_state` 用法一致，零迁移
- 前端交互：原生 JS `fetch` + AJAX，复用 Flask-WTF CSRF（`csrf_token()`）
- 数据库：SQLite（仅按 `id IN (...)` 精确查询，复用现有连接与 WAL 配置）

## 实现方案

### 策略

在「数据展示/详情」页通过 AJAX 调用新增的 `/toggle_interest` 路由维护 session 收藏集合；求职助手页从 session 读取收藏清单渲染为可勾选列表，提交时将勾选 id 列表作为 `target_job_ids` 传给 `review_resume`，由该函数把 SQL 从「模糊 LIKE 全量」改为「`WHERE id IN (...)` 精确命中」，Gap 分析与 LLM 上下文只围绕这些具体岗位 JD。

### 关键技术决策

1. **收藏用 session 而非新建表**：项目已有大量 session 状态先例，且演示数据量小；避免 DDL 迁移与 WAL 复杂度，符合 YAGNI。
2. **AJAX 切换收藏 + `event.stopPropagation()`**：`/data` 整行 `onclick` 跳转，按钮必须 `stopPropagation` 否则冲突；AJAX 返回 JSON `{interested, count}` 局部更新，避免整页刷新丢失分页位置。
3. **`target_job_ids` 作为可选参数**：保持 `review_resume` 向后兼容，未传时原兜底逻辑完全不变，降低回归风险。
4. **多选分别诊断**：清单默认全选，用户可取消勾选；`review_resume` 对每个命中岗位独立计算 Gap，结果区按岗位展示，与现有逐岗位卡片结构一致。

### 性能与可靠性

- `/toggle_interest` 仅读写 session 列表 + 返回 JSON，O(1)，无 DB 查询；CSRF 校验 + `job_id` 正整数校验（越界/非数字拒绝），防注入。
- `review_resume` 精确 `id IN (...)` 查询，命中集合通常很小（个位），比原 `LIKE` 全表扫描更轻；LLM 上下文仍限制前 5 个岗位控制 token 成本（沿用现有上限）。
- 深链支持 `/advice?tool=review&target_job_id=<id>` 预选单个岗位（从详情页按钮可扩展），与现有 `?clear_*` 清除模式一致。

## 实现注意事项

- `/toggle_interest` 为 POST，**必须带 CSRF token**（项目硬约束：新增 POST 接口需 CSRF，无 token 返回 400）。`/data`、`/job` 当前模板无 CSRF token，需在两页注入隐藏 input（如 `<input type="hidden" id="csrf-token" value="{{ csrf_token() }}">`），fetch 时从 `document.getElementById('csrf-token').value` 读取并放入请求头/表单字段。
- `job_id` / `target_job_ids` 元素必须 `isdecimal()` + 正整数校验，越界返回 400，避免 SQL 注入与异常。
- 不新增第三方依赖；不硬编码任何密钥；复用 `get_db()`/现有连接模式。
- 改动面控制在 session 读写、`review_resume` 参数、三个模板与两个测试文件，不触碰其他模块。
